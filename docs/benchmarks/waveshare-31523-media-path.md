# Waveshare 31523 media-path benchmark

Date: 2026-08-22  
Board: Waveshare ESP32-P4-WIFI6-Touch-LCD-3.4C, ESP32-P4 rev 1.3  
Display: 800 x 800 RGB565, two framebuffers, MIPI DSI 2-lane  
Target: 60 FPS (16,666 us frame deadline)

## Decision

Use a versioned sequence of baseline JPEG frames in a contiguous,
memory-mapped internal-flash show partition. Decode each frame with the ESP32-P4
hardware JPEG engine directly into the display's back framebuffer, then swap on
display refresh.

Do not stream show frames through LittleFS. Keep LittleFS for small metadata or
legacy GIF compatibility only.

For the show compiler:

- target at most 180 KB per 800 x 800 JPEG frame for reliable 60 FPS headroom;
- treat 212 KB as the measured diagnostic edge, not the production target;
- recompress, downscale, or schedule at 30 FPS when a frame cannot meet the
  180 KB budget;
- 320 KB high-entropy frames are a practical 30 FPS class on this board.

The display pixel clock is 45 MHz. With the configured 860 x 840 total timing,
the measured refresh period is about 16.4 ms. The vendor example uses 80 MHz,
which measured about 9.23 ms / 108 Hz and made a 60 FPS media schedule alternate
between inconvenient refresh boundaries.

Ticket #3 subsequently set the product player to 46 MHz. This gives its
timeline scheduler slight scan headroom above 60 Hz; the benchmark results
below remain the measured 45 MHz results used to select the media path.

## Payload

The reproducible `ZJBM0001` diagnostic payload contains eight deterministic,
baseline 800 x 800 JPEG frames:

| Frame | Class | JPEG bytes | Final p95 total | Final max total |
| --- | --- | ---: | ---: | ---: |
| graphic_a | flat graphics | 45,410 | 16.3 ms | 18.045 ms |
| graphic_b | flat graphics | 36,924 | 16.4 ms | 16.438 ms |
| gradient_a | gradients | 46,078 | 16.4 ms | 16.429 ms |
| gradient_b | gradients | 47,143 | 16.4 ms | 16.430 ms |
| texture_q35 | texture | 153,970 | 16.4 ms | 16.460 ms |
| texture_q55 | texture | 211,690 | 16.4 ms | 16.426 ms |
| texture_a | high entropy | 319,996 | 32.8 ms | 32.837 ms |
| texture_b | high entropy | 320,106 | 32.8 ms | 32.850 ms |

The assets are generated by
`tools/generate_jpeg_benchmark_assets.ps1`. The dedicated PlatformIO environment
is `esp32p4-benchmark`; benchmark-only assets are excluded from the normal
firmware.

## Rejected LittleFS path

A 3,600-frame probe through LittleFS at the vendor's 80 MHz display clock
completed without decode or display errors, but only achieved 19.68 FPS for the
mixed workload.

| Metric | Median | p95 | Maximum |
| --- | ---: | ---: | ---: |
| LittleFS read | 13.4 ms | 90.75 ms | 90.977 ms |
| Hardware JPEG decode | 6.6 ms | 8.95 ms | 8.992 ms |
| Present | 5.6 ms | 8.3 ms | 8.357 ms |
| Total | 27.7 ms | about 101.6 ms | 101.636 ms |

LittleFS reads took 11-15.5 ms for 37-47 KB frames and 84.5-90.8 ms for
320 KB frames. The filesystem, not the JPEG accelerator, was the bottleneck.

## Final endurance run

Configuration: memory-mapped internal flash, hardware RGB565 JPEG decode,
direct decode into the back framebuffer, 45 MHz pixel clock.

- 36,000 / 36,000 frames completed in 739.464 seconds;
- 0 decode errors, 0 present errors, 0 resets;
- effective rate for the deliberately mixed workload: 48.68 FPS;
- 9,001 60 FPS deadline misses: all 9,000 intentionally oversized 320 KB
  frames plus one transient miss on `graphic_a`;
- the other 26,999 frames up to 211,690 bytes met the deadline;
- PSRAM free: 30,364,316 bytes at both start and end;
- internal free heap: 231,144 bytes at start, 230,876 at end;
- largest internal block: 188,404 bytes at both start and end.

Overall timing:

| Metric | Median | p95 | Maximum | Mean |
| --- | ---: | ---: | ---: | ---: |
| Flash copy | 1.6 ms | 11.4 ms | 11.662 ms | 4.841 ms |
| Hardware JPEG decode | 6.8 ms | 8.4 ms | 8.497 ms | 7.209 ms |
| Present / refresh wait | 8.3 ms | 14.1 ms | 14.220 ms | 8.465 ms |
| Total | 16.4 ms | 32.8 ms | 32.850 ms | 20.519 ms |

No timing drift or memory loss was observed during the endurance run. The test
continued into the existing GIF after completion without a reset.

## Reproduction

```powershell
$env:PYTHONUTF8 = '1'
$env:PYTHONIOENCODING = 'utf-8'
& .\tools\generate_jpeg_benchmark_assets.ps1
& "$env:USERPROFILE\.platformio\penv\Scripts\platformio.exe" run `
  -e esp32p4-benchmark -t upload
& "$env:USERPROFILE\.platformio\penv\Scripts\platformio.exe" device monitor `
  -p COM6 -b 115200
```

The official Waveshare display configuration used as the hardware baseline is
`examples/arduino/libraries/displays/displays_config.h` in
<https://github.com/waveshareteam/ESP32-P4-WIFI6-Touch-LCD-XC>.
